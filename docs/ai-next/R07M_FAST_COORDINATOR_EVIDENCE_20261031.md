# R07M — Fast offline Controller/Advisor and durable old-request deduplication

Reference date: 31 October 2026. Base main: 3e5f70b007ca49edd11e4e2d733878e4853edcf9.

**UNMOUNTED; feature flag false. No production API, no migration, no deployed Firebase, no financial writes.**

R07M implements a separate server-authorized coordinator for only R05 deterministic greetings and new unsaved quotation drafts. Normal new/repeated/latest-turn processing uses R07L transactional current-turn/task/assistant state, not R03 full historical replay. R07J persists each step with atomic head CAS and SHA-256 event-chain integrity, scoped by all nine authenticated fields and current membership epoch. Real model providers are never contacted.

A second, opt-in R07M root `aiNextFastEventThreadsV1` is used instead of earlier R07J/R07L root `aiNextIndexedEventThreadsV1`. Each new turn creates a unique, SHA-indexed turn idempotency key and sealed start-event reference in the same Firestore transaction as the immutable event, head and materialized operational state. Retries detect the index and confirm sealed original event and request fields before resuming. A replay for a **historical** completed turn deliberately performs the expensive full R03 event replay audit before returning the old reply/draft. This exception is not taken on ordinary new/latest-turn steps, and the old key can never create a second turn. No old thread is silently migrated into the new indexed collection.

The coordinator still checks JWT authenticity via trusted verifier and exact current company/branch membership on every entrypoint, including replay, current state and full audit. Client role or owner claims are never accepted. Draft store verifies a revision-1 unsaved review-only quotation separately before assistant completion; missing/outage never becomes a successful task. No approve, finance execute, provider call, HTTP handler or production flag is enabled. Bounded retries cover only known transaction conflicts, not silent provider retries.

**Security and performance qualifications:** materialized SHA-256 is not an HMAC; a privileged datastore writer can forge content. Fast current-turn reads cannot certify every historical event or indexes from an independent writer, so full audits must remain an explicit safety gate for trusted recovery or any future financial approval, and backend IAM must prevent all untrusted writes. The new request index is opt-in and append-only, not designed for automatic backfill. Historical replay has O(history) cost; ordinary steps have bounded document reads but additional index writes. No real cloud p95/usage billing measurements, Cloud Firestore IAM/rules acceptance, physical two-device/iPhone test or T22-T24 approval is yet available.

Tests: synthetic mock 320 older events and bounded read count; end-to-end greeting and unsaved quote from separate coordinator instances; old key replay/collision, duplicate concurrent requests, broken draft/restart recovery, revoked company ACL and viewer rejection; official Firestore Emulator with two distinct Firebase Admin app clients and multi-turn history consistency. Merge only when these and GitHub CI pass.
